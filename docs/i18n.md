# Localization

Every word Pulse shows comes from a catalogue. This page is for anyone adding
a language or a new string.

## Where things live

- `ui/i18n/en.json` is the source catalogue. English is the fallback for
  every other language, so every key exists here first.
- `ui/i18n/<language>.json` or `ui/i18n/<language>_<REGION>.json` holds a
  translation, for example `pt.json` or `pt_BR.json`.
- `ui/I18n.qml` picks the locale, loads the catalogues, and formats messages.
- `ui/Rhythm.js` builds subdivision names from catalogue keys.

Qt's own translation system is not used. Quickshell installs no translator,
and a JSON file needs no build step to edit or test.

## Choosing the locale

Pulse reads the first of these that is set:

1. `PULSE_LANG`, to force a language for Pulse alone.
2. The first entry of `LANGUAGE`, when a real locale is also set.
3. `LC_ALL`, then `LC_MESSAGES`, then `LANG`.

`pt_BR.UTF-8` becomes `pt_BR`. `C` and `POSIX` mean English. Messages are
looked up in `pt_BR.json`, then `pt.json`, then `en.json`, key by key, so a
regional file only needs the words that differ from its language.

## Writing messages

A message is a string. Placeholders in braces are filled by the UI:

```json
"error.backendExited": "The backend exited with code {code}"
```

A translation may reorder placeholders but must not invent new ones. The test
suite checks this.

A message that depends on a count is an object of plural forms:

```json
"note.sixteenth": {
  "one": "sixteenth",
  "=2": "two sixteenths",
  "other": "{count} sixteenths",
  "all": "sixteenths"
}
```

- The CLDR categories `zero`, `one`, `two`, `few`, `many` and `other` are
  chosen by the language's plural rule. `other` is required.
- `=N` matches an exact count and wins over the category. Use it for number
  words, and for agreement where the count word changes with gender.
- `all` is the form for a whole cell made of one figure, as in
  "Sextuplet sixteenths". It has no count word.

Plural rules are built into `I18n.qml` for the languages CLDR groups
differently. A language not listed uses `one` for 1 and `other` for the rest.
Add its rule there if that is wrong.

## Subdivision names

A cell's name is assembled, never concatenated in code:

- Each figure has a key by kind, value and dot: `note.eighth`,
  `rest.sixteenth.dotted`. Values are `whole`, `half`, `quarter`, `eighth`,
  `sixteenth` and `thirtySecond`.
- Figures in a row join with `list.separator`.
- The joined list fills `{figures}` in `cell.plain`, `cell.triplet`,
  `cell.quintuplet` or `cell.sextuplet`.
- The first letter of the result is capitalized.

A translator who needs a different order moves `{figures}` in the template.

## Layout and direction

- A right-to-left language mirrors the window through `LayoutMirroring`.
- The beat bars, the time signature wheels, the notation and the note squares
  stay left to right in every language, because music notation does.
- Titles and captions are written in sentence case in the catalogue and
  uppercased by the font, so `ß` and similar letters are handled by Qt.
- Buttons with words grow with their label. Dialog titles elide. The keys
  sheet sizes its key column to the widest key cap and wraps descriptions.
- Key caps go through `I18n.shortcut`, which wraps them in a left-to-right
  isolate. Shortcuts read left to right in every language, so `1 2 4 8` and
  `shift ↑ ↓` keep their order inside right-to-left text.
- Text that must mirror sets its alignment explicitly. `LayoutMirroring`
  swaps an alignment that is set, not one Qt infers.

## Accessibility

Controls drawn as glyphs or figures carry an accessible name from the
`a11y.` keys: the close buttons, the tempo steppers, play, each beat, each
subdivision tile and each note square.

## Backend errors

The backend sends a stable `code` with every `error` event, plus `msg` in
English for logs and `detail` for the variable part, such as an OS error.
The shell looks up `error.wire.<code>` and may quote `{detail}`. The codes
are listed in `src/backend/proto.rs` and `docs/protocol.md`.

## What is not translated

- The name Pulse in the window title.
- Digits in the tempo, the time signature and tuplet numbers. Music uses
  Western digits everywhere.
- The command line's usage and stderr messages, which are for developers.
- The `detail` of a backend error, which comes from the operating system.

## Testing

Two pseudo-locales show untranslated or clipped text without a real
translation:

```sh
PULSE_LANG=pseudo ./target/release/pulse       # accented, lengthened, bracketed
PULSE_LANG=pseudo-rtl ./target/release/pulse   # the same, mirrored right to left
```

Any plain English word left on screen is a string that bypasses the
catalogue. A bracket missing its closing `⟧` is text being cut off.

`cargo test` fails when:

- a key used in `ui/` is missing from `en.json`,
- a catalogue is malformed, has a key `en.json` lacks, or uses a placeholder
  the source does not fill,
- a `text`, `label`, `title` or accessible name in QML is a literal word.

`tests/ui.sh` checks plural rules, fallback, mirroring and live retranslation.

## Adding a language

1. Copy the keys you translate from `ui/i18n/en.json` into
   `ui/i18n/<language>.json`. Leave out any key that should stay English.
2. Check the language's plural categories in `I18n.qml` and add a rule if it
   is missing.
3. Run `cargo test` and `tests/ui.sh`.
4. Run Pulse with `PULSE_LANG=<language>` and open every dialog.
